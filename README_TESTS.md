# Тесты Stellar Burger

В комплекте ваши исходники src, тесты Jest и Playwright, HAR-моки и настройки тестирования.

## Как перенести в существующий проект

1. Откройте корневую папку stellar-burgers — ту, где находится ваш package.json.
2. Скопируйте туда содержимое архива. Папки src, tests и scripts объедините с существующими. Подтвердите замену файлов из src. Ваш package.json и настройки сборки в архив не включены.
3. Откройте терминал в этой папке и выполните команды по одной:

```sh
node scripts/setup-tests.cjs
npm install
npx playwright install chromium
npm test
npm run test:e2e
npm run test:coverage
```

Скрипт setup-tests.cjs добавляет devDependencies и команды тестирования в package.json, сохраняя зависимости приложения и остальные команды. Команды с именами test, test:watch, test:coverage, test:e2e и test:e2e:ui заменяются настройками этого комплекта. После npm install сохраните в git также обновлённый package-lock.json.

Playwright сам запускает приложение через npm run start и ожидает http://localhost:4000. Если ваш проект запускается другой командой или на другом порту, исправьте command, url и baseURL в playwright.config.ts. Остановите ранее запущенный сервер перед первым запуском, чтобы тесты использовали актуальные исходники.

API для HAR: https://norma.education-services.ru/api. Это значение задано в webServer.env.BURGER_API_URL. Если ваша сборка берёт адрес исключительно из .env, укажите там BURGER_API_URL=https://norma.education-services.ru/api.

Если в проекте уже есть другая конфигурация Playwright или Jest, используйте новые команды: в них явно указан нужный файл конфигурации. Нужен установленный TypeScript; он обычно уже есть в этом учебном проекте. Jest использует отдельный tsconfig.jest.json и не изменяет основной tsconfig.

В .gitignore добавьте:

```gitignore
coverage/
playwright-report/
test-results/
```

## Что проверяется

### Jest — 23 теста

- ingredients: неизвестный экшен с undefined и готовым состоянием, pending, fulfilled, fulfilled с пустым списком и rejected.
- burgerConstructor: начальное состояние, неизвестный экшен, добавление и замена булки, добавление начинки и соуса, разные id повторяющихся ингредиентов, удаление нужного экземпляра, перестановка в обе стороны, очистка, создание заказа.
- createOrder.fulfilled очищает конструктор. pending и rejected не обрабатываются этим слайсом, поэтому отдельно проверяется сохранение бургера при ожидании и ошибке.
- Редьюсеры вызываются напрямую; обращения к реальному API нет.

### Playwright — 6 тестов

- Добавление двух частей булки, котлеты и соуса, проверка суммы.
- Открытие модального окна и проверка данных выбранного ингредиента.
- Закрытие по крестику, по оверлею и по Escape.
- Полный заказ: токены в cookie/localStorage до открытия страницы, получение пользователя, сборка, проверка POST-состава и заголовка авторизации, номер 123456, очистка конструктора, закрытие окна.
- Ответы ingredients, auth/user и orders находятся в tests/hars/constructor.har.
- Все запросы **/api/** проходят через page.routeFromHAR. Неизвестные запросы блокируются (notFound: abort). Настоящий заказ не создаётся.

## Изменения приложения

В src/components/ui/modal/modal.tsx добавлены role="dialog", aria-modal и доступное название окна. Обработчик закрытия перенесён с иконки на кнопку: теперь вся кнопка, включая нажатие с клавиатуры, закрывает окно. Бизнес-логика слайсов не менялась.

## Проверка и ограничения

Архив-источник содержал только src. Поэтому тесты проверены на отдельной временной Vite-сборке этих исходников, а не на исходной конфигурации вашего репозитория. Временные package.json, lock-файл, index.html и Vite-конфиг в комплект не включены: их не нужно переносить поверх вашего проекта.

Jest: 23/23. Playwright Chromium: 6/6. Проверка типов тестов Playwright: успешно. Сборка на временной конфигурации: успешно.

Покрытие строк constructorSlice.ts — 100%, ingredientsSlice.ts — 92,85%. Все ветвления обоих слайсов — 100%. Не покрыт вызов getIngredientsApi внутри thunk, который не относится к обработчикам редьюсера.

После npm run test:coverage откройте coverage/index.html. После npm run test:e2e отчёт доступен через npx playwright show-report. При падении браузерного теста сохраняется trace в test-results.
